Design Ethos

The six non-negotiable principles behind MC Perception. They are not aspirations — they are the checklist every screen must pass before it ships. Function over decoration, always.

6 Principles AA Verified Function First
The Test

Before any MC Perception screen is considered done, it must pass all six principles below. Use them as the checklist for anything you build or review.

1 The Six Principles

Each principle is a constraint, not a suggestion. Together they make the system predictable: any component, on any surface, in any hue, behaves the way these rules promise.

01
Function over decoration

Every pixel serves information. There is no ornament and no noise — if an element does not help comprehension, it does not belong on the screen.

02
Strict color discipline

Seven engineered hues across ten luminance steps — nothing more. Never an ad-hoc hex, never opacity to fake a shade; always a real palette step.

03
Universal surfaces

One component renders correctly on all five surface modes — white, black, light hue, dark hue, and mid hue. The same code, every background.

04
Accessibility, always

Every foreground and background pair is audited for WCAG AA contrast. Accessibility is built into the palette math, not bolted on at the end.

05
Predictable API

Every component is base plus variant plus hue plus size — no special cases. Learn the pattern once and it holds across the entire library.

06
Data-dense first

Built for dashboards, trading desks, and monitoring tools — not brochures. The system optimizes for fast reading under real working conditions.

2 Why It Matters

These principles compound. A strict palette makes contrast verifiable; verifiable contrast makes universal surfaces safe; safe surfaces make a predictable API possible. Constraint is what makes the system fast to use.
