3. Input States

Every input must provide clear visual feedback for its current state. Use both color and border thickness changes — never rely on color alone.

Default (Empty)
Idle state. Ready for input.
Filled (Has Value)
User has entered data.
Focused
Field is selected. Border brightens + ring.
Disabled
Non-editable. Reduced opacity.
Read-Only
Displays value. Can select/copy but not edit.
Error / Invalid
Amount must be a positive number
Success / Valid
Username is available
Warning
High leverage increases liquidation risk

7. Validation Patterns

Validate after the user leaves a field (blur), not while they are still typing. Remove errors immediately when corrected. Error messages must be specific and constructive.

8. Accessibility

RequirementGuidelineImplementation
Label Association <label for="id"> must match <input id="id"> Screen readers announce the label when field is focused
Error Messages Use aria-describedby linking to error text Adds aria-invalid="true" on error
Required Fields Use aria-required="true" or required attribute Visual asterisk via mc-required + ARIA attribute
Color Contrast Text: 4.5:1 ratio (WCAG AA) White on black inputs ensures high contrast
Focus Indicator Visible ring on keyboard focus Built-in: ring-1 + border color change
Placeholder Never use as label substitute Always pair with mc-label above the input
Error Announcement Use aria-live="polite" on error container Announces errors to screen readers dynamically

9. Do’s and Don’ts

Do

Do

Always use a visible label above the input

Do

Use single-column layout for forms

Do

Show errors after the user leaves the field, not while typing

Do

Provide specific, actionable error messages

Do

Mark optional fields as “optional” rather than marking required with *

Do

Use outlined inputs — they have the best affordance

Don’t

Don't

Don’t use placeholder text as the field label

Don't

Don’t validate while the user is still typing initial input

Don't

Don’t use vague errors like “Invalid input”

Don't

Don’t rely on color alone to indicate state changes

Don't

Don’t add “Retype password” — use show/hide toggle instead

Don't

Don’t use underline-only inputs — poor discoverability
