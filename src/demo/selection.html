1. When to Use Which Control

Each selection control serves a specific purpose. Using the wrong control creates confusion and delays.

Control Selection Effect Options Best For
Checkbox Multiple (0, 1, or many) Requires form submit Independent options Filters, preferences, multi-select lists
Radio Button Single only (1 of N) Requires form submit 2-5 mutually exclusive Order type, account type, payment method
Switch / Toggle Binary on/off Immediate (no submit) Always 2 states Settings, feature toggles, dark mode
Choice Chips Single or multiple Varies Compact labels Filters, tags, timeframes, categories

6. Accessibility

Requirement Guideline Implementation
Touch Target Min 48×48px clickable area mc-control wraps control + label, expanding the tap target
Label Clickability Labels must toggle the control Use <label> wrapping both input and label text
Keyboard Navigation Tab to focus, Space to toggle Native <input> elements provide this for free
Radio Arrow Keys Arrow keys navigate within radio group Use same name attribute and fieldset
Focus Ring Visible focus indicator Built-in: ring-1 ring-p-neutral-600
Grouping Group related controls semantically Use <fieldset> + <legend> for screen readers
Indeterminate Announce mixed state Set via JS: el.indeterminate = true + aria-checked="mixed"

7. Do’s and Don’ts

Do

Do

Use checkboxes for independent, non-exclusive options

Do

Always pre-select one radio button in a group

Do

Use switches for settings that take immediate effect

Do

Stack options vertically for better scanning

Do

Make labels clickable to expand the touch target

Don’t

Don't

Don’t use circular checkboxes — they look like radio buttons

Don't

Don’t use a switch inside a form that has a Submit button

Don't

Don’t use radio buttons for more than 5 options — use a dropdown

Don't

Don’t leave all radio buttons unselected — one must be default

Don't

Don’t use negative wording like “Don’t send emails”
